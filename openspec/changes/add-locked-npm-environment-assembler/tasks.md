# Binding Implementation Contract

Every checkbox and phase deliverable is required. Within each phase work SHALL proceed RED → GREEN → INTROSPECT → VALIDATE. Later phases may depend only on earlier phases listed below; changing an earlier delivered contract reopens its affected introspection and validation.

```text
Phase 1 ──> Phase 2 ──┬──> Phase 3 ──┐
                      └──> Phase 4 ──┼──> Phase 5 ──> Phase 6
                                     ┘
```

## 1. Locked Input and Identity Contract

**Depends on:** none.

**Deliverables:** closed lockfile-v3 DTO; exact roots/closure/range validation; supported optional omission model; assembler and environment identities.

- [ ] 1.1 RED — Add failing table-driven tests for valid lockfile-v3 roots, scoped packages, nested placement and integrity, and verify no closed parser exists.
- [ ] 1.2 RED — Add failing tests for root drift, unsatisfied ranges, missing nodes, unsafe paths/URLs, missing SRI, and file/git/link/workspace/bundled nodes.
- [ ] 1.3 RED — Add failing tests for platform-applicable and platform-omitted optional nodes with explicit omission evidence.
- [ ] 1.4 RED — Add failing identity tests covering canonical roots, lock bytes, image digest, Node/npm versions, script/policy digests and platform.
- [ ] 1.5 GREEN — Implement immutable lock/root/optional DTO parsing and verify tasks 1.1–1.3 pass without effects.
- [ ] 1.6 GREEN — Implement canonical assembler/environment identities and verify task 1.4 passes.
- [ ] 1.7 INTROSPECT — Enumerate every accepted package-lock field and prove unsupported fields cannot influence output silently.
- [ ] 1.8 INTROSPECT — Compare npm range/placement semantics used by validation with fixtures generated by the pinned npm version and close every discrepancy.
- [ ] 1.9 VALIDATE — Run lock, range, URL, SRI, path, optional and identity tests plus type checks and verify Phase 1 is green.
