## Why

The project runs a single container, but currently maintains Compose files, generated Compose fragments, command classification, and a separate `build_wrapper.py` orchestration path. Direct `docker build` and `docker run` commands generated by the existing Python tools can provide the same behavior with one less configuration and orchestration layer.

## What Changes

- **BREAKING** Replace the user-facing `versions.py`, `launch-pi.py`, Compose, and wrapper workflows with `docker/docker-constructor.py` as the sole public CLI facade.
- Provide primary facade commands `build`, `run`, and `check-updates`, plus auxiliary commands `validate`, `show`, `doctor`, and `verify`; defer a public `schema` command.
- Keep the facade thin: it parses and validates user arguments, handles prompts and output, maps errors to exit codes, and delegates versioning, networking, launcher, update, verification, and Docker behavior to independently testable internal APIs.
- Keep `docker-constructor.toml` as the single reviewed dependency source, with explicit `build` and `runtime` sections and closed typed models for each phase.
- Make `build` resolve build overrides into a host-only effective build projection, diagnose host gateway state, and invoke `docker build` directly; make `run` resolve runtime overrides into a minimal effective runtime projection and construct a direct `docker run` invocation.
- Never copy or mount the reviewed source or effective build projection into the runtime image; build versions, artifact URLs, checksums, provider metadata, and override policy remain host-side.
- Mount only the generated effective runtime projection read-only so internal entrypoint/installer APIs receive exact effective package identities, versions, artifacts, checksums/integrity, and validation metadata needed for runtime-installed Pi extensions.
- Move rootless gateway diagnosis and override handling behind the internal networking API and remove `docker/build_wrapper.py`; retain existing operational host settings separately for now because dynamic versus immutable host configuration is out of scope.
- Remove Compose YAML files, project fragments, `COMPOSE_FILE` handling, and generated Compose overrides.
- Remove the unused `docker/gen-models-json.py` integration with `inf-splitter`, including `PROXY_PORT`, `INF_SPLITTER_CONFIG_DIR`, `INF_SPLITTER_SECRETS_DIR`, and its obsolete networking contract.
- Update tests, verification helpers, scripts, and maintained documentation to use the new commands.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `build-networking`: Move gateway diagnostics, rootless override application, and build integration behind reusable internal APIs consumed by the constructor facade.
- `docker-build-reproducibility`: Make direct `docker build` the canonical consumer of the build section and its host-only effective projection, generate a separate minimal runtime projection, and remove Compose-specific resolver behavior.
- `docker-runtime`: Define direct Docker build/run behavior, read-only effective runtime projection exposure, runtime extension installation/validation, and removal of the Compose service and fragment contract.
- `project-launcher`: Launch the selected projects with a direct `docker run` argument vector instead of generated Compose files.

## Impact

- Removes `docker/build_wrapper.py`, Compose YAML files, project fragments, and `docker/gen-models-json.py`; operational dotenv cleanup is deferred with the broader dynamic-configuration decision.
- Changes CLI commands documented in README files and consumed by tests and verification scripts.
- Adds `docker/docker-constructor.py`; internalizes versioning, launcher, networking, update, and verification behavior; removes standalone user-facing entry points.
- Affects internal API modules, rootless helper scripts, runtime verification, and Docker acceptance tests.
- Replaces the single broad effective inventory with two generated projections from one reviewed source: a host-only effective build projection and a minimal read-only effective runtime projection; preserves the runtime image tag, project mount semantics, entrypoint ownership repair, and `host.docker.internal` behavior.
